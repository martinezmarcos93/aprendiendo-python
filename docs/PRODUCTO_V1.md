# TortuScript — Definición de Producto V1

## 1. Qué es

TortuScript es una plataforma progresiva de aprendizaje tecnológico para niños y adolescentes.

El producto no se define por un único lenguaje. Su recorrido inicial enseña primero a comprender el mundo digital, después programación con Python y luego competencias de Web y datos.

La implementación actual sigue siendo local. La V1 prepara el producto para una futura publicación web comercial sin convertir esa futura infraestructura en dependencia del producto educativo local.

## 2. Recorrido V1

El recorrido conceptual es:

1. Alfabetización tecnológica.
2. Python.
3. Web esencial: HTML + CSS + JavaScript.
4. SQL.
5. Proyecto integrador.
6. Puerta de entrada al nivel avanzado.

La secuencia representa dependencias pedagógicas, no necesariamente una única ruta obligatoria para todos los alumnos.

Python es el bloque de mayor profundidad de la V1.

Web esencial tiene como objetivo comprender, leer, modificar y depurar interfaces pequeñas.

SQL tiene profundidad intermedia: debe permitir consultar y relacionar datos de forma funcional, pero no pretende cubrir todavía ingeniería de datos avanzada.

## 3. Nivel 0: alfabetización tecnológica

Antes de exigir sintaxis de programación, el alumno debe adquirir un vocabulario operativo mínimo.

Conceptos iniciales:

- programa;
- lenguaje de programación;
- código;
- navegador;
- servidor;
- frontend;
- backend;
- red;
- Internet;
- API;
- datos;
- base de datos;
- seguridad.

La enseñanza será interactiva y basada en situaciones. No será un curso teórico extenso.

## 4. Python

Python es el eje técnico de la V1.

Debe cubrir, con profundidad progresiva:

- pensamiento computacional;
- valores y tipos;
- variables;
- entrada y salida;
- condiciones;
- repetición;
- funciones;
- listas y estructuras de datos básicas;
- resolución de problemas;
- depuración;
- tortuga;
- proyectos;
- transición de TortuScript a Python real;
- introducción a creación de juegos.

El contenido existente de TortuScript se reutiliza cuando sea pedagógicamente válido; no se considera automáticamente definitivo por existir.

## 5. Web esencial

Web enseña el modelo mental de una interfaz web.

HTML:
- estructura del documento;
- elementos;
- atributos;
- texto, enlaces, imágenes y contenedores;
- relación entre estructura y contenido.

CSS:
- selectores;
- clases;
- propiedades básicas;
- dimensiones;
- espacio;
- disposición elemental.

JavaScript:
- variables;
- valores;
- funciones;
- eventos;
- selección y modificación elemental del DOM;
- depuración de errores sencillos.

El objetivo no es memorizar cientos de elementos ni producir grandes cantidades de frontend manual.

Los ejercicios deben producir resultados visibles y pequeños productos interactivos.

## 6. SQL

SQL introduce el pensamiento sobre datos estructurados:

- tablas;
- filas y columnas;
- claves;
- SELECT;
- WHERE;
- ORDER BY;
- funciones de agregación;
- GROUP BY;
- JOIN;
- relaciones;
- modificaciones básicas;
- seguridad básica y uso responsable de consultas.

Los ejercicios usarán bases pequeñas y contextos concretos: inventarios, personajes, detectives, bibliotecas, ciudades y otros mundos comprensibles para el alumno.

## 7. Proyecto integrador

La V1 debe contener al menos un proyecto que haga visible la relación entre tecnologías.

La integración objetivo es:

HTML/CSS/JS → interfaz
Python → lógica
SQL → datos

No se pretende construir una arquitectura de producción completa. El objetivo es que el alumno pueda explicar qué papel cumple cada pieza y seguir el recorrido de un dato o una acción.

## 8. Edad como dimensión del producto

La edad no será simplemente un filtro visual.

El currículo podrá adaptar:

- vocabulario;
- longitud de las explicaciones;
- densidad de código;
- abstracción;
- duración;
- autonomía;
- dificultad;
- estética;
- tipo de proyecto;
- forma de presentar errores y pistas.

Las franjas numéricas definitivas no quedan fijadas en Fase 1. Se decidirán después de la investigación pedagógica de Fase 3.

La plataforma debe permitir que dos alumnos estudien la misma competencia con actividades diferentes según su etapa.

## 9. Gamificación

Se conservan los mecanismos que aporten valor educativo:

- XP;
- niveles;
- logros;
- rachas;
- práctica;
- proyectos;
- progreso.

La gamificación no debe convertirse en el objetivo de la experiencia ni en una fuente de presión innecesaria.

La V1 mantiene la liga local existente y no incorpora comunidad, chat, perfiles públicos ni ranking mundial.

## 10. IA

La IA se considera una herramienta dentro de la alfabetización tecnológica.

El alumno deberá progresivamente aprender a:

- leer código generado;
- identificar errores;
- describir cambios;
- comprobar resultados;
- distinguir una explicación correcta de una respuesta plausible pero incorrecta;
- utilizar IA sin abandonar los fundamentos.

La V1 no requiere un tutor IA completo.

## 11. Acceso y modelo comercial

La visión comercial contempla contenido gratuito y contenido premium.

En V1 se modela el concepto de acceso, pero no se implementan:

- pagos;
- facturación;
- suscripciones reales;
- cuentas cloud;
- autenticación;
- sincronización.

Estados conceptuales:

- gratuito;
- premium;
- prueba;
- bloqueado por prerrequisito;
- no publicado.

Importante: **V1 no fija todavía qué itinerarios completos son gratuitos o premium.**

La hipótesis de producto es ofrecer un recorrido inicial suficientemente útil de forma gratuita y utilizar contenido posterior, proyectos o niveles avanzados como posibles superficies premium. La distribución exacta se decidirá con validación de producto antes de implementar cobros.

El motor educativo solamente debe responder a una decisión abstracta de disponibilidad.

## 12. Qué entra en V1

Entra:

- núcleo técnico estable;
- modelo curricular extensible;
- alfabetización tecnológica;
- Python V1;
- Web esencial;
- SQL;
- proyecto integrador;
- competencias;
- prerrequisitos;
- diferenciación por edad;
- progreso y gamificación existentes estabilizados;
- modelo conceptual de acceso;
- preparación arquitectónica para futura web comercial;
- privacidad y protección de menores documentadas;
- mapa del nivel avanzado;
- documentación y testing.

## 13. Qué no entra en V1

No entra:

- pagos reales;
- facturación;
- SaaS completo;
- sincronización cloud definitiva;
- aplicación móvil nativa;
- comunidad;
- chat;
- perfiles públicos;
- ranking mundial;
- tutor IA completo;
- todos los cursos avanzados;
- analítica comercial sofisticada;
- internacionalización completa.

## 14. Criterios de aceptación de producto

La V1 puede considerarse definida cuando:

1. Existe una secuencia curricular explícita.
2. El catálogo puede representar edad, nivel, dificultad, competencia y prerrequisitos independientemente.
3. Python está identificado como itinerario principal.
4. Web y SQL tienen alcance definido sin competir con la profundidad de Python.
5. Existe un proyecto integrador.
6. El sistema puede representar estados de acceso sin conocer un proveedor de pagos.
7. La edad puede modificar la experiencia sin duplicar el motor.
8. El nivel avanzado tiene fuentes curriculares externas identificadas.
9. La futura capa cloud/comercial está separada del runtime educativo.
10. El alcance de V1 y lo que queda fuera están documentados.
11. No existe ninguna dependencia de cuentas, pagos o cloud para ejecutar el producto local.
12. Las decisiones que requieren investigación posterior están explícitamente marcadas como hipótesis y no como hechos.

## 15. Principio rector

TortuScript debe enseñar primero a comprender y después a construir.

La plataforma no debe intentar enseñar todas las tecnologías con la misma profundidad. Debe construir un núcleo sólido de pensamiento computacional y Python, utilizar Web y SQL para ampliar el modelo mental de una aplicación y dejar preparado el camino hacia desarrollo de aplicaciones, datos, infraestructura e IA.
