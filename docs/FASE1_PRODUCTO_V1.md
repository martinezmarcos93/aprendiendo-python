# Fase 1 — Especificación de Producto V1 — 29/09/2026

## Estado

Fase 1 en ejecución sobre `refactor/auditoria-2026-09-29`.

Este documento convierte la visión de producto en criterios verificables. No autoriza todavía cambios de arquitectura ni implementación de la Fase 2.

## Decisiones consolidadas

- TortuScript se define como plataforma progresiva de aprendizaje tecnológico.
- La V1 inicial recorre alfabetización tecnológica, Python, Web esencial, SQL, proyecto integrador y puerta de entrada al nivel avanzado.
- Python es el itinerario de mayor profundidad.
- Web prioriza comprensión, lectura, modificación y depuración.
- SQL tiene profundidad intermedia.
- La edad es una dimensión curricular y no solamente visual.
- Las tres fuentes avanzadas permanecen externas.
- El acceso se modela conceptualmente y queda desacoplado de pagos.
- La asignación exacta de contenido gratuito/premium permanece como hipótesis hasta validación.
- La V1 no requiere cuentas, cloud, pagos ni SaaS para funcionar localmente.
- La IA se enseña como herramienta crítica y no sustituye los fundamentos.
- La comunidad y el ranking mundial quedan fuera de V1.

## Criterios de aceptación

La definición de producto queda satisfecha cuando el catálogo, el motor y el contenido puedan evolucionar siguiendo estas reglas sin redefinir el producto:

1. Una unidad puede describir edad, nivel, dificultad, competencia y prerrequisitos por separado.
2. Una competencia puede aparecer en diferentes edades y actividades.
3. El acceso puede cambiar sin modificar el contenido.
4. Un contenido puede permanecer local aunque exista una futura capa cloud.
5. Los repositorios curriculares externos no son dependencias de ejecución.
6. El producto puede agregar nuevos itinerarios sin convertir Python, Web o SQL en una dependencia rígida del motor.
7. La futura identidad adulta/infantil permanece separada del runtime local.
8. Las decisiones todavía dependientes de investigación están identificadas como hipótesis.

## Hipótesis que pasan a fases posteriores

- franjas de edad definitivas;
- lenguaje y estética por edad;
- distribución concreta gratuito/premium;
- profundidad exacta de cada unidad;
- validación con alumnos;
- requisitos legales concretos según mercado;
- arquitectura comercial final.

## Fuera de Fase 1

No se implementan todavía:

- nuevo motor curricular;
- nuevas lecciones;
- sistema de cuentas;
- pagos;
- sincronización;
- CMS;
- SaaS;
- cambios de runtime;
- rediseño completo de UX.

## Próxima dependencia

La Fase 2 deberá transformar esta especificación en un modelo curricular implementable, pero no comienza automáticamente por cerrar Fase 1.
