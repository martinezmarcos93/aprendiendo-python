# TortuScript — Roadmap V1
## 29/09/2026 → 31/12/2026

## Objetivo
TortuScript dejará de considerarse únicamente un curso de Python y pasará a tratarse como la base de una plataforma progresiva de aprendizaje tecnológico para niños y adolescentes.

La V1 de diciembre debe ser una plataforma educativa fundacional, no el SaaS definitivo. Debe tener un núcleo técnico estable, currículo inicial coherente, modelo de contenido extensible, diferenciación por edad, Python como itinerario principal, alfabetización web con HTML/CSS/JS, SQL, proyectos integradores, progreso, gamificación, documentación, seguridad y un mapa del nivel avanzado.

## Fase 0 — 29/09–05/10 — Auditoría y congelación
- Auditar el estado real de main y comparar con auditorías históricas.
- Identificar problemas ya resueltos para no duplicar trabajo.
- Ejecutar tests, validador de contenido y verificaciones disponibles.
- Revisar ADR-001 a ADR-015 y corregir contradicciones documentales.
- Actualizar README y documentación obsoleta.
- Mantener la rama refactor/auditoria-2026-09-29 como rama de consolidación.

Entregable: estado técnico verificable al 05/10.

## Fase 1 — 06/10–12/10 — Producto V1
- Definir TortuScript como plataforma, no como curso aislado.
- Definir el itinerario inicial: alfabetización tecnológica → Python → Web esencial → SQL → proyecto integrador → nivel avanzado.
- Definir conceptualmente el acceso gratuito/premium sin implementar pagos todavía.
- Definir qué significa producto terminado para diciembre.

Entregable: PRODUCTO_V1.md.

## Fase 2 — 13/10–19/10 — Arquitectura curricular
- Extender el modelo conceptual de contenido para edad, nivel, competencias, prerrequisitos, duración, dificultad, fuente curricular y acceso.
- Separar competencia técnica, dificultad y edad recomendada.
- Diseñar catálogo independiente de la implementación actual del motor.

Entregable: modelo curricular V1.

## Fase 3 — 13/10–26/10 — Investigación de edades
Usar franjas configurables como hipótesis iniciales, sin fijar todavía límites rígidos. Investigar vocabulario, densidad de código, abstracción, duración, autonomía, estética y tipos de desafío adecuados a cada etapa.

Entregable: marco de edades y criterios pedagógicos.

## Fase 4 — 20/10–02/11 — Consolidación técnica
- Auditar traductor, runtime, AST, límites de ejecución, progreso y TortuGame.
- Añadir pruebas de conformidad donde existan dos runtimes.
- Corregir vulnerabilidades o inconsistencias críticas.
- Congelar el núcleo para V1 salvo bugs o ADR nuevas.

Entregable: núcleo técnico estable.

## Fase 5 — 27/10–09/11 — Nivel 0
Crear un diccionario interactivo del mundo digital: programa, lenguaje, navegador, servidor, frontend, backend, API, red, Internet, datos, base de datos y seguridad.

Debe ser breve, visual y basado en desafíos, no un curso teórico largo.

## Fase 6 — 03/11–20/11 — Python V1
Convertir el contenido existente en un itinerario curricular definitivo: pensamiento computacional, variables, datos, condiciones, repetición, funciones, listas, problemas, tortuga, proyectos, Python real y juegos.

Cada unidad debe combinar explicación, reconocimiento, predicción, construcción, código y desafío.

## Fase 7 — 10/11–30/11 — Web esencial
Construir HTML + CSS + JavaScript como alfabetización web. La meta es comprender, leer, modificar y depurar una interfaz, no memorizar cientos de elementos ni producir grandes volúmenes de código manual.

Proyectos sugeridos: ficha de personaje, página de criatura, interfaz de héroe, botones interactivos, mini juego y reparación de páginas rotas.

## Fase 8 — 20/11–07/12 — SQL
Construir una progresión desde tablas y SELECT hasta filtros, agregaciones, JOIN, relaciones y seguridad básica. Usar mundos de juego, detectives, inventarios, bibliotecas y ciudades como contextos.

## Fase 9 — 01/12–10/12 — Proyecto integrador
Crear un proyecto pequeño que conecte HTML, CSS, JavaScript, Python y SQL. El objetivo pedagógico es comprender cómo las piezas de una aplicación se relacionan.

## Fase 10 — 08/12–15/12 — Sistema de producto
Modelar catálogo, competencias, progreso y estados de acceso. El motor pedagógico no debe depender de una implementación concreta de pagos.

Estados de acceso previstos: gratuito, premium, prueba, bloqueado por prerrequisito y no publicado.

## Fase 11 — 15/12–20/12 — Preparación web/comercial
Documentar la arquitectura futura de cuenta adulta, perfiles infantiles, catálogo, progreso sincronizado, acceso y suscripción. No implementar todavía el SaaS completo.

## Fase 12 — 15/12–22/12 — Privacidad y menores
Definir datos recopilados, minimización, consentimiento parental, perfiles, eliminación, exportación, retención, logs, analítica y terceros. Revisar requisitos jurídicos por mercado antes de operar comercialmente.

## Fase 13 — 15/12–23/12 — UX y diferenciación por edad
Revisar lenguaje, estética, densidad, interacción y motivación según edad. La identidad puede ser común, pero su expresión debe evolucionar para evitar infantilizar a adolescentes.

## Fase 14 — 20/12–27/12 — Nivel avanzado
Mapear curricularmente curso-python-datos, curso-desarrollo-aplicaciones y curso-orquestacion-streaming-llm. No copiarlos dentro de la plataforma: serán fuentes curriculares externas que se adaptarán por edad y prerrequisitos.

## Fase 15 — 23/12–28/12 — Release candidate
Freeze de features. Ejecutar tests técnicos, contenido, evaluación, runtime, seguridad, UI, accesibilidad, responsive, instaladores, migraciones y simulaciones pedagógicas.

## Fase 16 — 29/12–31/12 — V1.0.0
Actualizar README, CHANGELOG, ADRs, arquitectura, contenido, testing y documentación de seguridad. Crear el tag v1.0.0.

## Fuera de alcance de V1
- Pagos reales y facturación.
- SaaS completo.
- Sincronización cloud definitiva.
- Aplicación móvil nativa.
- Comunidad.
- Tutor IA completo.
- Todos los cursos avanzados.
- Analítica comercial sofisticada.
- Ranking mundial.
- Internacionalización completa.

## Criterio de terminado
La V1 está terminada cuando el núcleo es estable, el currículo inicial está completo, existe Nivel 0 + Python + Web esencial + SQL + proyecto integrador, el modelo de competencias y acceso está definido, la privacidad futura está documentada, los tres repositorios avanzados están mapeados y existe una release v1.0.0 verificable.
